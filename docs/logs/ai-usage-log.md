# AI usage log — QXU6028 group G18

Scope: this log covers every substantive use of a generative assistant in producing the
submission. Tool: DeepSeek Harness, a command-line coding assistant (model: DeepSeek V3 series),
used from a local workspace between 5 and 15 November 2026. No other generative tool was used
for code, text or figures.

How the assistant was used, and what it did not decide:

| Phase | What the assistant produced | What the team fixed before accepting |
|---|---|---|
| L1 forward model | First draft of the two quadrature routines, the closed form for the Fermi count, and the plotting function | Integration limits, the value of N_A and its meaning, the definition C = n_band/n_F, and the decision to report the working point at 0.176 eV rather than at the 0.10 eV used in the brief |
| L2 inversion | First draft of the cone/gap model pair, the normalised model library, the nearest-point residual and the resampling loop | Separate normalisation of R_H and R_xx, retention of the sign of R_H, the 15 per cent selection rule, and the reading of the resampled interval as a grid-resolution bound rather than a confidence interval |
| L3 reconstruction | First draft of the projector, the Tikhonov solve, the sensitivity sweep, the FWHM probe and the noise floor | That the zero-mean constraint acts on m and not on d, the choice of eta0 as the reference value, and the 8-neighbour rule for merging features |
| Report | First draft of all six sections from a results file produced by the pipeline | Structure, the claim that model choice dominates the pass/fail uncertainty, the Transfer section argument, and every number quoted |
| Integrity documents | Drafts of this log, the error ledger and the self-assessment | What to record, which errors count as physical, and the wording of the weaknesses |

Verification trail. Every number in the report is written by the pipeline, not by the assistant:

```
python reproduce.py                  # 7 figures + results/results.json, exits non-zero on any failed check
python -m unittest discover -s tests -v   # 18 assertions
python run_blind.py                  # blind set, 13.1 s, writes blind_results.json
```

The assistant's output was accepted only when (i) the arithmetic gate in the relevant stage
passed, (ii) the unittest suite passed, and (iii) the reported number could be traced to a key in
`results/results.json`. Four assistant errors that failed these conditions are recorded in
`error-ledger.md`, each with the test that exposed it.

Extent, stated plainly: the assistant wrote first drafts of most of the Python and of the English
prose. The physical model, the choice of gates, the interpretation of the results and the
corrections belong to the team, and every submitted number was regenerated by the committed code
after those corrections. Each member can explain the files they own (see `contribution.md`).
